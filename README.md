# OKX 合约行情分析 + 15 分钟级缠论模拟交易

| 文件 | 作用 |
|---|---|
| `方法论.md` | 从《基础分享课程》整理出的分析方法论，外加合约数据层（订单簿 / OI / 资金费率 / 多空比 / CVD） |
| `okx_analyzer.py` | 单次深度分析：拉数据 → 计算 → 汇总关键位 → 草拟情景 → 调用 DeepSeek 写报告 → 程序复算盈亏比 |
| `trader15.py` | **主策略**：15 分钟级缠论交易（v2：8 个品种、窄中枢、只做多），常驻循环实时扫描，严格止损，记录胜率和利润；可选同步下单到 OKX |
| `okx_trade.py` | OKX 下单：逐仓、市价开多 + 附带交易所止损单、平仓撤单、仓位历史对账 |
| `okx_live_check.py` | 下单前自检：Key、账户模式、余额、各品种张数与保证金；`roundtrip` 在模拟盘上走一遍开平仓 |
| `ta.py` | 课程里的指标和形态识别 |
| `okx_client.py` | OKX 公共行情接口（不需要 API Key） |
| `config.example.json` | 配置模板。复制为 `config.json` 并填 Key，或用环境变量 `LLM_API_KEY` |
| `deploy/install.sh` | Linux 服务器一键部署（systemd 定时器 + 看板 + 看门狗） |
| `watchdog.py` | 看门狗：检查心跳，超过 5 分钟没更新就自动拉起 |

依赖：`pip install -r requirements.txt`

## 深度分析报告

```bash
python okx_analyzer.py ETH-USDT-SWAP
python okx_analyzer.py SOL-USDT-SWAP --no-llm   # 只算数据，不调用大模型
```

近期有 FOMC、CPI、非农等事件时，可写进 `config.json` 的 `events`。

## 模拟交易（主策略：15 分钟级缠论，`trader15.py`）

默认只模拟，不下任何订单，也不需要 OKX 账户（可选同步下单到 OKX，见下方“OKX 下单”）。当前为**策略 v2**，规则来自 `chan15_lab2.py` 的控制变量测试（8 个品种 + 窄中枢 + 只做多）：

- **品种**：ETH / BTC / SOL / XRP / DOGE / SUI / ZEC / HYPE，每个品种各自最多一个仓位；1 倍 ≈ 2500U 名义价值（ETH 1 个、BTC 0.03 个、SOL 20 个……见 `trader15.py` 的 `DEFAULT_CFG`）。
- **入场**：15m 新确认的三买做多，按当前价成交，不加仓。**不做空**：90 天回测里空单在两段都亏（胜率 11–25%）。
- **仓位**：固定 1 倍（与回测一致）。`sizing` 设为 `"step"` 可改回按评分分档 0.5 / 1 / 2 / 3 / 5 倍（`sizing.py`）。
- **过滤**：
  - 大方向：1H（0.6）+ 4H（0.4）加权趋势分不能明显相反。
  - 区间套：1H 缠论方向（走势 + 近期买卖点）不能相反。
  - 只做趋势：1H 近 48 根 K 线的趋势效率（净涨跌 ÷ 逐根涨跌绝对值之和）≥ 20%。
  - **窄中枢**：15m 最近中枢宽度（ZG − ZD）≤ 1.5 倍 ATR(15m)。窄幅盘整后的突破更真，宽幅震荡后的突破多半被拉回止损。
- **止损**：买卖点价外 0.5 倍 ATR(15m)。用 1 分钟 K 线逐根判定，按止损价原价成交（不计滑点）。
- **离场**：止损，或持仓中 15m 出现反向买卖点就按当时价格平仓；不设固定止盈。
- **手续费和资金费**（`fees.py`）：
  - 交易手续费 = 成交金额 × OKX 吃单费率，开平仓各收一次（开仓、止损、反向离场都是市价单）。
    - 配置 OKX **只读** API Key 后，取你账户的真实费率：复制 `okx_api.example.json` 为 `okx_api.json` 并填写，或设置环境变量 `OKX_API_KEY` / `OKX_API_SECRET` / `OKX_API_PASSPHRASE`。
    - 不配置时，按 OKX 普通用户 Lv1 标准费率：吃单 0.05%。
  - 资金费：持仓期间每经过一个 OKX 结算时刻，按实际资金费率计（费率为正时多付空收）。
  - 在 `trader15_config.json` 里把 `fee_mode` 设为 `"fixed"`，可改回每 1 倍固定 2U。
- **记录**：数据存在 `trader15.db`，看板在 `web/index.html`（每 60 秒自动刷新）。
- **从 v1 升级**：第一次运行时自动把 `trader15_config.json` 里的策略项（品种、入场点、效率门槛、中枢宽度、仓位）改成 v2，
  告警、费用等其他设置保留；旧配置备份为 `trader15_config.v1.json`，旧成交记录归档为 `trader15_v1.db`，看板从零开始统计 v2。

```bash
python trader15.py loop      # 常驻：算完一轮马上接着算（部署默认方式）
python trader15.py run       # 只跑一轮
python trader15.py report    # 胜率、利润、持仓、最近成交
```

**回测参考**（90 天，8 个品种，固定 1 倍，吃单 0.05% + 实际资金费；“上月”= 最近 30 天，“验证”= 再往前 60 天）：

| | 每周笔数 | 胜率 上月 / 验证 | 净利 上月 / 验证 | 最大回撤 上月 / 验证 | 去掉最赚 5 笔 上月 / 验证 |
|---|---|---|---|---|---|
| v1 规则（效率≥25%，多空） | 5.6 | 29% / 22% | +362 / +171U | 146 / 406U | −326 / −735U |
| 效率≥20%，多空 | 8.6 | 27% / 27% | +305 / +1041U | 155 / 473U | −413 / −491U |
| 窄中枢，多空 | 3.5 | 40% / 32% | +515 / +1149U | 44 / 203U | −120 / −125U |
| **v2：窄中枢 + 只做多（当前）** | **2.8** | **50% / 50%** | **+573 / +1276U** | **44 / 104U** | **−63 / +2U** |

- 按 1 万 U 本金：最近 30 天 +5.7%，30–60 天 +12.8%，60–90 天 −0.1%。90 天里最多同时 5 个持仓，名义价值最高约 1.1 万 U。
- **样本小**：90 天只有 34 笔。**行情偏多**：这 90 天这些品种几乎全涨（ETH +55%、ZEC +107%），只做多占了行情的便宜；
  下跌行情里预计大多数三买会被大方向 / 区间套挡掉而少开单，但这段数据里没有下跌行情可以验证。
- 实盘代码与回测一致性：把最近 30 天回测开过仓的 12 个时刻的 K 线喂给 `trader15.handle()`，12 笔入场价、止损全部一致；
  因中枢太宽被回测过滤的 15 笔，实盘也全部放弃。
- 回测脚本：`python chan15_lab2.py 90`（首次运行约 10 分钟拉数据，缓存在 `bt/`）。v1 的研究见 `chan15_lab.py` / `bt_sizing.py`。

### OKX 下单（可选）

模拟交易仍是唯一的决策者，开启后每笔开平仓同步到 OKX：

- **一律逐仓**：下单 `tdMode=isolated`，设杠杆 / 平仓 `mgnMode=isolated`；只做多。
- **止损挂在交易所上**：市价开多时附带止损单（最新价触发、市价成交），程序断线或崩溃也会止损；成交后核对止损单确实挂上，没有就补挂，补挂失败立即平仓。
- **离场**：策略反向离场或模拟止损时，市价全平并撤掉剩余止损单。交易所先止损时，模拟交易继续按自己的规则跟踪（两边独立统计）。
- **对账**：每轮核对 OKX 持仓；平掉的仓位从仓位历史补记真实开平均价、手续费、资金费和净盈亏，看板上显示“OKX 实际净利”。
- **仓位**：模拟交易固定每个品种约 2500U（与回测一致，便于对照）；OKX 默认按账户权益开仓，所以两边的盈亏金额不同，比较时看收益率。
- **出错不影响模拟交易**：下单失败只记录并告警；下单请求返回异常但交易所其实已成交时，按交易所持仓接着跟踪。

配置（`okx_api.json` + `trader15_config.json`）：

1. 复制 `okx_api.example.json` 为 `okx_api.json`，填写带“交易”权限的 Key（不要勾提现，绑定服务器 IP 白名单）。模拟盘 Key 设 `"simulated": true`。
2. 服务器上先自检：`python okx_live_check.py`（只读 + 设置逐仓杠杆）；模拟盘可再跑 `python okx_live_check.py roundtrip` 用最小数量走一遍开平仓。
3. `trader15_config.json` 里设 `"live_trading": true`，按需调整 `live_leverage`（默认 10）和仓位，然后重启服务。
   - 仓位默认 `"live_sizing": "equity"`：每笔名义价值 = 开仓时 OKX 账户 USDT 权益 × `live_equity_frac`（默认 1，即每笔 1 倍）。
     逐仓 10 倍时每笔保证金 = 权益 10%，8 个品种可以同时持仓，但合计名义价值最多到权益的 8 倍（每笔止损约亏权益的 0.9%）。
     保证金不够时该笔跳过、记录原因（模拟交易照常）。
   - `"live_sizing": "fixed"`：下单数量 = 模拟仓位 × `live_size_factor`（每个品种约 2500U 名义价值 × 系数）。
4. **真实账户**（`simulated` 为 false）还必须把 `live_allow_real` 设为 `true`，否则安全锁生效、只做模拟。

OKX 模拟盘没有 ZEC、HYPE 两个合约，模拟盘阶段这两个品种会记为“下单失败”，模拟交易照常。

## 稳定性：断网、检活、自动恢复

**运行方式**：`trader15.py loop` 常驻运行，算完一轮马上接着算，两轮之间默认只隔 1 秒（`loop_interval_sec`，设为 0 就完全不停）。
实测约 1 秒一轮，只占约 3% 的单核 CPU，2 核服务器完全够用。信号在 15m 收盘后约 1 秒内就能发现；
只要 K 线的结束时间已过就视为收盘，不等 OKX 的确认标记。回测中入场晚 5 分钟少赚约 2.5%，晚 10 分钟少赚约 7%（`python bt_latency.py 120`）。

| 情况 | 处理方式 |
|---|---|
| 单次请求失败 / OKX 繁忙 | 最多重试 5 次，指数退避（1、2、4、8 秒…，最长 20 秒） |
| 断网 | 先检测能否连上 OKX；连不上就跳过本次、记录错误，下次自动继续 |
| **断网期间碰到止损** | **不会漏**：恢复后用 1 分钟 K 线从上次检查点逐根回放，按止损价补记（最多约 50 小时） |
| 单轮出错 | 只记录错误，不退出，继续下一轮 |
| 进程崩溃 / 被杀 | Linux：systemd `Restart=always`，5 秒内重启、开机自启；Windows：看门狗每分钟检查，最长约 6 分钟恢复 |
| 重复运行 | 操作系统级文件锁（Linux `flock` / Windows `msvcrt.locking`）：同一时间只能有一个实例，第二个启动会立即退出；进程被杀后锁由系统立刻释放，重启不会被旧锁挡住 |
| 无声崩溃 | Windows 后台运行没有控制台，崩溃信息写入 `trader15.err`；`faulthandler` 连解释器级硬崩溃也会留下调用栈；进程正常退出也会在日志里记一笔 |
| 卡死 | 看门狗 `watchdog.py` 检查心跳 `heartbeat.json`，超过 5 分钟没更新就结束旧进程并重新拉起（Linux 上重启 paper-trader 服务） |
| 看板服务挂了 | Linux 上 `Restart=always` 自动重启，看门狗也会检查 |
| 重启电脑 / 服务器 | Linux 服务开机自启；Windows 登录后自动启动 |

看板顶部会显示运行状态（常驻模式下每 10 秒刷新一次）。如果页面超过 5 分钟没更新，浏览器里会直接显示红色警告，即使程序完全停止也能看到。

**告警推送（可选）**：在 `trader15_config.json` 里填写以下任一项即可开启：
- `alert_webhook`：钉钉 / 企业微信群机器人地址
- `telegram_bot_token` + `telegram_chat_id`：Telegram 机器人

开启后，连续失败 3 次、以及恢复正常时都会推送。把 `alert_trades` 设为 `true`，开仓 / 平仓时也会推送。

## 部署到 Linux 服务器（CentOS 7/8/9、Rocky、Alma、Ubuntu、Debian）

```bash
cd /opt && git clone https://github.com/taisuishen/tradetest.git && cd tradetest
sudo bash deploy/install.sh 8080
```

- 安装脚本会自动找 Python 3.9 及以上版本；找不到时，CentOS 8/9 用 dnf 安装 python3.11，CentOS 7 用 uv 下载独立的 Python 3.11。
- firewalld 在运行时，脚本会自动放行看板端口；云厂商的安全组需要另外手动放行。
- 看板地址是 `http://服务器IP:8080/`。看板没有登录密码，建议安全组只允许自己的 IP 访问。
- 建议装在 `/opt` 下：SELinux 开启时，放在家目录里可能被拦截。
- 服务器需要能访问 www.okx.com：美国 IP 可能被 OKX 限制，建议用香港、新加坡或日本的机房。
