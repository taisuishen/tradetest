# OKX 合约行情分析 + 15 分钟级缠论模拟交易

| 文件 | 作用 |
|---|---|
| `方法论.md` | 从《基础分享课程》整理出的分析方法论，外加合约数据层（订单簿 / OI / 资金费率 / 多空比 / CVD） |
| `okx_analyzer.py` | 单次深度分析：拉数据 → 计算 → 汇总关键位 → 草拟情景 → 调用 DeepSeek 写报告 → 程序复算盈亏比 |
| `trader15.py` | **主策略**：15 分钟级缠论模拟交易，每 5 分钟运行一次，严格止损，记录胜率和利润 |
| `ta.py` | 课程里的指标和形态识别 |
| `okx_client.py` | OKX 公共行情接口（不需要 API Key） |
| `config.example.json` | 配置模板。复制为 `config.json` 并填 Key，或用环境变量 `LLM_API_KEY` |
| `deploy/install.sh` | Linux 服务器一键部署（systemd 定时器 + 看板 + 看门狗） |
| `watchdog.py` | 看门狗：检查心跳，停止超过 15 分钟自动拉起 |

依赖：`pip install -r requirements.txt`

## 深度分析报告

```bash
python okx_analyzer.py ETH-USDT-SWAP
python okx_analyzer.py SOL-USDT-SWAP --no-llm   # 只算数据，不调用大模型
```

## 模拟交易（主策略：15 分钟级缠论，`trader15.py`）

只模拟，不下任何真实订单，也不需要 OKX 账户。规则来自 `chan15_lab.py` 的控制变量测试（区间套 + 大方向过滤 + 只做三类买卖点 + 只做趋势）：

- **入场**：15m 新确认的三买做多、三卖做空，按当前价成交，不加仓。
- **仓位（动态分档）**：按信号 / 趋势强弱评分开 0.5 / 1 / 2 / 3 / 5 倍（1 倍 = ETH 1 个 / BTC 0.03 个），见 `sizing.py`。
  - 评分权重是事先定好的，没有按回测结果调：大方向同向程度 30%、1H 趋势效率 30%、1H 缠论已成同向趋势 20%、4H ADX 20%。
  - 分档规则：评分 <0.2 开 0.5 倍，<0.4 开 1 倍，<0.6 开 2 倍，<0.8 开 3 倍，≥0.8 开 5 倍。
  - 在 `trader15_config.json` 里把 `sizing` 设为 `""` 可恢复固定 1 倍。
- **过滤**：
  - 大方向：1H（0.6）+ 4H（0.4）加权趋势分不能明显相反。
  - 区间套：1H 缠论方向（走势 + 近期买卖点）不能相反。
  - 只做趋势：1H 近 48 根 K 线的趋势效率（净涨跌 ÷ 逐根涨跌绝对值之和）≥ 25%，震荡行情里的突破不做。
- **止损**：买卖点价外 0.5 倍 ATR(15m)。用 1 分钟 K 线逐根判定，按止损价原价成交（不计滑点）。
- **离场**：止损，或持仓中 15m 出现反向买卖点就按当时价格平仓；不设固定止盈。
- **手续费**：每笔平仓每 1 倍扣 2U（5 倍即 10U）。
- **记录**：数据存在 `trader15.db`，看板在 `web/index.html`（每 60 秒自动刷新）。

```bash
python trader15.py run       # 执行一次（定时任务每 5 分钟调用）
python trader15.py report    # 胜率、利润、持仓、最近成交
```

**回测参考**（最近 120 天，ETH + BTC，已扣手续费，未计资金费率）：

| | 笔数 | 胜率 | 平均倍数 | 前 60 天 | 后 60 天 | 120 天净利 | 最大回撤 | 收益回撤比 |
|---|---|---|---|---|---|---|---|---|
| 只做趋势，固定 1 倍 | 38 | 28.9% | 1.00 | +290U | +285U | +575U | 138U | 4.17 |
| **只做趋势 + 动态分档（当前）** | 38 | 28.9% | 2.64 | +1000U | +1110U | **+2110U** | 262U | **8.05** |
| 对照：固定 2.64 倍 | 38 | 28.9% | 2.64 | +768U | +753U | +1521U | 364U | 4.17 |

- **动态分档比同等平均仓位多赚约 39%，回撤反而更小**。评分越高的单子胜率越高：评分 0.2–0.4 的 7 笔全亏，评分 ≥0.8 的 7 笔胜率 43%。
- **样本很小，利润也很集中**：只有 38 笔，其中 08-20 一笔 ETH 5 倍多单就贡献了约四成利润。
- **需要较高杠杆**：两个合约同时开 5 倍时，名义仓位约 25,000U。实盘还有滑点、资金费率和连续亏损的风险，表现大概率比回测差。
- 回测脚本：`python bt_sizing.py 120`

## 稳定性：断网、检活、自动恢复

程序不依赖长连接：每 5 分钟由系统定时器启动一次、跑完就退出，所以不会出现“连接断了卡死”的情况。

| 情况 | 处理方式 |
|---|---|
| 单次请求失败 / OKX 繁忙 | 最多重试 5 次，指数退避（1、2、4、8 秒…，最长 20 秒） |
| 断网 | 先检测能否连上 OKX；连不上就跳过本次、记录错误，下次自动继续 |
| **断网期间碰到止损** | **不会漏**：恢复后用 1 分钟 K 线从上次检查点逐根回放，按止损价补记（最多约 50 小时） |
| 程序卡死 | 单次运行限时 4 分钟，超时强制结束 |
| 重复运行 | 运行锁保证同一时间只有一个实例；异常退出留下的旧锁 5 分钟后自动清理 |
| 程序停了 | 看门狗 `watchdog.py` 每 10 分钟检查心跳 `heartbeat.json`，超过 15 分钟没运行就自动拉起（Linux 上还会重启 systemd 定时器） |
| 看板服务挂了 | Linux 上 `Restart=always` 自动重启，看门狗也会检查 |
| 重启电脑 / 服务器 | 定时器开机自启，并补跑错过的那次 |

看板顶部会显示运行状态。如果页面超过 15 分钟没更新，浏览器里会直接显示红色警告，即使程序完全停止也能看到。

**告警推送（可选）**：在 `trader15_config.json` 里填写以下任一项即可开启：
- `alert_webhook`：钉钉 / 企业微信群机器人地址
- `telegram_bot_token` + `telegram_chat_id`：Telegram 机器人

开启后，连续失败 3 次、以及恢复正常时都会推送。把 `alert_trades` 设为 `true`，开仓 / 平仓时也会推送。

## 研究工具

| 脚本 | 用途 |
|---|---|
| `chan15_lab.py 120 [base\|opt\|regime]` | 15m 缠论控制变量实验台：一次只改一个因素，并按前后两半检验。base=买卖点与出场方式，opt=提高胜率的尝试，regime=行情性质过滤 |
| `bt_annual.py 120` | 主策略的年化、回撤和按月净利 |
| `bt_sizing.py 120` | 动态仓位与“同等平均仓位”的公平对照，以及评分分档的单笔表现 |
| `sizing.py` | 信号 / 趋势强弱评分与仓位分档（回测与实盘共用） |
| `chan.py` | 缠论实现：包含处理 → 分型 → 笔 → 笔中枢 → 趋势 / 盘整背驰 → 三类买卖点 |
| `paper_trader.py` / `backtest.py` | 备选：小时级马丁分批挂单（0.2 / 0.4 / 0.8 / 1.6 / 3.2 倍）及其回测 |
| `backtest_chan.py` / `chan_strategy.py` | 1H 级缠论单仓策略回测 |
| `bt_parallel.py` | 回测多进程加速（16 核下 60 天回测从约 15 分钟降到约 35 秒） |

> 马丁分批挂单的 60 天回测胜率 89–93%，但净亏 −741U。高胜率不代表赚钱，详见 `backtest.py`。

## 部署到 Linux 服务器

```bash
git clone https://github.com/taisuishen/tradetest.git && cd tradetest
sudo bash deploy/install.sh 8080
```

装好后每 5 分钟自动运行一次。看板地址是 `http://服务器IP:8080/`，需要在云厂商安全组放行 8080 端口。
服务器需要能访问 www.okx.com：美国 IP 可能被 OKX 限制，建议用香港、新加坡或日本的机房。
